# 红果客厅 TV 架构

界面继续使用系统 View。TvUi 定义尺寸、文字和配色；TvActivity 统一大屏密度、安全边距与全窗口方向焦点路由，避免 ScrollView 将跨区上键误处理成局部滚动。MainActivity 的内容请求按世代隔离，精选和片库使用不同布局，分类快切会丢弃旧请求。CatalogRepository 只保存有界公共片单快照，后台刷新失败保留当前内容。

HistoryStore 是本机完整片库的唯一来源，按账号与作品主键保存真实位置和日期。未知旧日期保持为零，界面明确标注；历史与待补传共用同一行，确认必须匹配原观看时间、集号、位置和视频 ID，旧响应不能清掉新进度。移除历史创建本机隐藏时间戳，旧云记录不会在下次刷新立即重新出现，重新观看可以再次生成记录。

LibraryRepository 串行执行云同步和上传。完整云历史按服务端游标继续读取，检测重复页和不前进的游标；每页提交成功后才刷新显示，后页失败保留前页结果。收藏读取失败不覆盖本机副本。当前账号凭据在任务开始时快照，网络操作前后都验证账号，切换后不会把旧账号数据显示到新片库。

ProgressContract 明确两个业务数据形状。read_history/update 使用数字 book_id 和 current_play_position；read_progress/upload 使用字符串 book_id/item_id 与 current_play_time。两份共用同一真实 read_timestamp_ms。先读取两份新鲜记录，手机更新得更晚时采用手机记录；部分上传成功时保留待同步记录，下次补齐两份。不会按最大集数拒绝真实回看。

播放器保存当前实际解码槽对应的毫秒位置。选集、停止与换画质的异步响应使用请求世代隔离；进入后台后准备完成也不会开始播放。倍速切换保留暂停状态。媒体缓存单独限制空间，不淘汰完整观看历史。

1.3.0 将季发现与播放接续分开。SeasonSearch 按主标题查询候选，最多四页、40 部；Api.seasonDetails 按 20 部一批先读取候选身份。真实批量响应可能省略集列表或官方季关系，因此 SeasonRepository 只对已匹配季，以及严格同标题家族但缺少官方身份的候选进行单剧补读；补读结果仍须通过关系校验，不为无关搜索结果加载完整集列表。集数使用 `total_episode` 或视频列表中唯一的正 `vid_index`，不使用搜索卡片的集数估计。

SeasonMatcher 核对官方 `related_album_id`、`season_index` 与内容类型；`is_multi_season` 省略时仍可采用官方 album 和季号，显式关闭时拒绝官方多季关系。标题降级匹配仅用于概览。自动续季要求同一官方 album、连续 index 与可播首集，重复季号或缺少可播首集时不自动跳转。

SeasonRepository 共享最多 128 部季概览，同剧并发合并一次读取；成功关联缓存十分钟，单季或歧义结果缓存两分钟，读取失败不缓存。返回快照防止界面修改共享数据。SeriesDialog 分开加载选集和季概览，按请求世代丢弃旧结果；详情切季只替换元数据，不写入观看历史，季信息失败可局部重试。

PlayerActivity 在本季末三集查询下一季，末集通过原 EpisodePreparer 串行准备首集文件，不增加并行 MediaPlayer。SeasonPlaybackCoordinator 用剧 ID、账号身份和请求世代约束准备及完成事件；暂停、seek、隐藏、换号与手动改选撤销旧自动续播。只有目标文件就绪、官方季关联可靠、自动连播开启且页面仍前台时才提交切季；提交先保存旧季实际进度，再更新剧 ID、标题、封面、选集和追剧状态。画质、倍速、画面模式与自动连播偏好保留，旧季弹窗关闭，过期收藏回调丢弃。

切季提交同步更新 Activity Intent 的当前季、集列表、index 和位置；onSaveInstanceState 将这些字段以及画质、倍速、画面模式、自动连播和播放意图写入 Bundle。恢复前核对账号 session 身份，身份变化时退出旧播放，避免系统重建后回到旧季或串入另一个账号。

当前集与下一季准备各有 PreparationCancellation。手动播放优先取消过期准备，取消同时中断工作线程、断开正在阻塞读取的 socket，下载、拷贝和解密循环检查取消状态。取消的请求不回调失败提示；解密或拷贝先写 `.part`，准备完整后通过同目录重命名原子提交为可播放文件，失败或取消清除中间文件，避免把部分缓存误识别为整集。

1.1.2 将取流失败、进度、画质和准备完成回调统一经过 postLoad：回到主线程后同时核对请求世代与 isFinishing/isDestroyed，消除后台检查通过后页面已经退出的间隙。媒体回调还核对当前 MediaPlayer 实例与请求世代；退出解绑监听、清空待播放文件、取消本页面 Handler 任务和弹窗。剧集输入为空时允许在缓存未初始化的状态下安全退出。

原登录设备身份与签名桩保留，正式包仍采用原包名与签名。短信登录和 MFA 的端到端验证独立于可用会话恢复、协议测试及匿名视频解码，未经执行不能写成通过。

1.3.1 将签名链路改为国内 SDK 注册的 JNI 分发调用：首次用 TV 自己的设备/安装标识初始化 manager，按真实请求体字节生成安全头。Api 的手机播放器 POST 先压缩再签名，Http 同步计算实际发送字节的摘要；账号 POST 也传入同一份字节，不再生成随机 body digest。当前正式包仅 ARM64，避免把尚未适配的旧 ARM32 海外组件作为国内签名器交付。

当前模型从官方内容类型 1004 的视频 ID 桶定位，TrackPicker 保留嵌套或顶层的加密信息以及全部备用 URL。EpisodePreparer 串行尝试同集主地址和官方备用 CDN，下载完整且解密有视频样本后才提交缓存；失败可重新读取该视频模型一次，取消后立即停止。旧失败请求的凭据形态诊断落盘已移除，日志只记录响应类型、状态与字节数。

1.2.0 在独立 QrLoginManager 中管理官网二维码与轮询。OfficialQrTransport 只访问白名单 HTTPS 授权地址，短期上下文留在内存；QrMobileVerifier 使用候选账号读取手机信息、历史、收藏，全部通过才由 Account.commitQr 在账号锁内复核起始身份并保存。账号页切换、返回与销毁会释放扫码线程和授权上下文。二维码直接解码服务端 PNG/JPEG，无需 WebView 常驻或额外二维码运行库。
